# 💎 璀璨宝石 · Splendor 网页版

一款参考经典桌游《璀璨宝石 / Splendor》核心机制的网页版游戏：
**单机可玩（双击即开），也可联机对战（2~4 名真人 + 可选 AI 补位，服务器权威防作弊）**。手机与电脑使用同一房间协议，可以直接跨设备对战。

纯 **HTML + CSS + 原生 JavaScript** 实现；联机仅依赖一个轻量 Node 服务器（`ws`）。

---

## 🚀 怎么启动

### 方法一：单机（最简单）

直接双击 **`index.html`**（或兼容入口 `璀璨宝石.html`），浏览器即玩。
无需安装、无需联网。

> 若页面空白或按钮无反应，请确认 7 个 JS 文件（`data.js` / `game.js` / `aiConfig.js` / `ai_expert_weights.js` / `ai.js` / `net-client.js` / `ui.js`）与 `index.html` 在同一目录，并按 `Ctrl+F5` 强制刷新。

### 方法二：局域网联机（和朋友一起玩）

需要 [Node.js](https://nodejs.org)（≥ 14）：

```bash
# 首次运行安装依赖（只需 ws 一个库）
npm install ws --no-audit --no-fund

# 启动服务器（默认端口 3000，可用 PORT 环境变量修改）
node server.js
```

启动后终端会显示本地与局域网地址，例如：

```
💎 璀璨宝石服务器已启动
   本地访问:  http://localhost:3000
   局域网访问: http://192.168.x.x:3000
```

玩法：你自己用电脑或手机打开 `http://localhost:3000`，朋友在同一局域网打开
`http://192.168.x.x:3000` → 点击「🌐 联机对战」→ 房主「创建房间」
（选人数 2~4 与 AI 难度，人数不足由电脑补位）→ 把**房间码**发给朋友
→ 朋友「加入房间」→ 房主点「开始游戏」。

### 方法三：部署到公网（把游戏变成一个网址）

**⚠️ 本项目依赖 WebSocket 长连接，不能部署到纯静态托管**
（GitHub Pages / Netlify 静态站等）。请选择支持 **Node.js + WebSocket** 的平台。
项目已自带 **`Dockerfile` + `render.yaml` + `railway.toml`**，部署几乎是一键完成：

| 平台 | 做法 | 备注 |
| --- | --- | --- |
| **Render**（推荐） | 项目推 GitHub → render.com 新建 **Blueprint** 选该仓库 → 自动读取 `render.yaml`，点 Deploy | 免费额度够用；免费实例休眠后首次打开慢几秒属正常 |
| **Railway** | 推 GitHub → railway.app「Deploy from GitHub repo」→ 自动读取 `railway.toml` | 免配置 |
| **Vercel** | 推 GitHub → 新建项目，Framework Preset 选 **Other**（Node 服务型，非静态），自动读取 `vercel.json` | WebSocket 支持随套餐而异，长期稳定优先前两者 |
| 自建服务器（含国内云） | 有 Docker：`docker build -t splendor . && docker run -p 3000:3000 splendor`；无 Docker：`node server.js` | 国内玩家多时推荐，延迟最低 |

**通用流程（三平台一致）**：

1. 把项目文件夹推到 GitHub 仓库（`node_modules/`、`.npm-cache/` 已由 `.gitignore` 排除）；
2. 在平台新建项目并连接该仓库；
3. 平台自动识别部署配置（`render.yaml` / `railway.toml` / `vercel.json` / `Dockerfile`），无需手填命令；
4. 等待 1~5 分钟，得到一个 `https://xxx...` 网址；
5. 把网址发给朋友，打开即玩；平台自动启用 HTTPS，前端自动使用 `wss://` 连接。

部署到公网后，玩家不需要连接同一个 Wi-Fi：手机 5G、异地电脑或其他网络都能通过同一网址和房间码进入同一局。

> 本地先验证 Docker 镜像：`docker build -t splendor . && docker run -p 3000:3000 splendor`，浏览器打开 `http://localhost:3000`。

**❓ 部署后访问主页显示 Not Found 怎么办？**

1. 打开平台的服务日志（Render 顶部 Logs / Railway Deployments → View Logs），看启动输出：
   - `[static] 根目录: ...`、`[static] index.html 存在: true/false`、`[static] 文件清单: ...`
     这三行能直接判断问题：
   - **`index.html 存在: false` 或文件清单里没有页面文件** → 部署包缺少文件。
     检查 GitHub 仓库里是否有 `index.html`、`style.css`、`data.js` 等（本地确认后重新 push）；
     若用 Docker，检查 `.dockerignore` 是否误排除（不应排除 `index.html` 与各运行时 js）。
   - **`index.html 存在: true` 但仍 404** → 把日志中的 404 行（`[static] 404 ... -> ...`）发给我们排查。
   - **完全没有 `[static]` 日志** → 服务没启动成功，看更早的构建/启动报错。
2. 免费实例休眠后首次访问会慢几秒（平台在唤醒实例），稍等再刷新。
3. 服务器已做健壮性处理：**静态根目录自动定位**（兼容脚本目录与工作目录不一致的部署）、
   支持 `/`、`/index.html`、带 query 的请求；目录穿越请求会被拒绝（403）。

## 🎮 基本规则

**目标**：先达到 **15 分** 并保持优势。威望来自「发展卡」和「贵族」。

**每回合三选一**：

| 行动 | 说明 |
| --- | --- |
| 💎 拿宝石 | 3 种不同颜色各 1 枚；或同色 2 枚（该色公共区需 ≥ 4 枚）。黄金不能直接拿 |
| 🃏 预留卡 | 拿 1 张公开卡（或点「盲抽预留」从牌堆顶盲抽），同时获得 1 黄金；最多预留 3 张，预留的卡只能自己买 |
| 🛒 购买卡 | 支付「卡面成本 − 永久宝石折扣」，缺口可用黄金代替任意颜色 |

**关键规则**：

- **永久宝石**：购买的发展卡提供对应颜色的永久折扣，永久生效；
- **筹码上限**：回合结束时最多持有 **10 枚**（含黄金），超出必须归还（归还可撤销）；
- **贵族**：永久宝石达到要求自动获得（+3 分）；同时满足多位时只能选 1 位；
- **终局**：某玩家达到 15 分后**不立即结束**，所有人完成相同回合数后结算；
- **胜负**：分数高者胜 → 同分时发展卡更少者胜 → 仍相同则平局。

- [x] **手机版高密度圆桌 UI**：一屏上半区固定展示贵族、三层共 12 张发展卡和六色公共宝石；下半区以圆桌方位同时展示四名玩家的分数、筹码、永久折扣、发展卡数、预留卡数和贵族数；底部操作栏固定可触达；
- [x] **手机 / 电脑互通**：移动端和桌面端仅布局不同，游戏状态、房间码和操作协议完全一致，可进入同一联机房间对战；
- [x] **圆桌桌游化 UI**：顶部细状态栏 + 中央公共桌面（贵族陈列 + 三层发展卡 + 公共宝石池筹码区）+ 围桌座位 + 右侧信息栏（操作提示/快速提示/游戏日志）+ 玩家主座位（底部中央），当前行动者座位呼吸高亮；
- [x] **固定高度滚动日志**：页面高度不随日志增长；新日志自动滚动到底部；
- [x] **电脑上回合行动精确展示**：结构化 `lastAction`（拿宝石颜色×数量；购买显示卡牌颜色/分值/**原始印刷成本**；公开预留显示层级/颜色/分值/成本+获黄金；**盲抽预留只显示层级+获黄金，不泄露隐藏卡**；获得贵族追加显示）；
- [x] **发展卡固定卡位补牌**：每层固定 4 个卡位，新牌原位补入被拿走的槽位；牌堆耗尽时槽位留空；新牌淡入动画；
- [x] 官方结构牌库：发展卡 90 张（L1×40 / L2×30 / L3×20），贵族按人数抽取（人数+1 位，每位 +3 分）
- [x] **2 / 3 / 4 人模式**：公共宝石按官方规则（2 人 4/色、3 人 5/色、4 人 7/色，黄金恒 5）；多人局 AI 策略适配；L6 专家按人数分别训练权重；
- [x] **六档电脑 AI 难度**（1 新手 / 2 简单 / 3 标准 / 4 困难 / 5 高手 / 6 专家，默认「简单」）：L1~L5 共享评分框架仅调参数；L6 使用自我对弈 + 进化策略训练权重（2 人局对 L5 胜率约 76%）；所有难度仅使用**可观察状态**（不偷看牌堆/对手预留卡），防作弊；
- [x] 主菜单：开始游戏 / 难度拉条 / 人数拉条 / 规则手册；游戏中顶栏显示难度与全员分数徽章；
- [x] 三种行动、折扣/黄金支付、10 枚上限与归还（可撤销）、撤销上一回合（单局 3 次）、贵族判定、15 分终局、三档胜负判定；
- [x] 回合横幅、音效开关、规则弹窗、响应式布局、AI 调试模式（控制台 `SplendorAIConfig.setDebug(true)`）

### 联机（V1.7 新增）
- [x] **房间制**：创建房间获得房间码，2~4 名真人加入，不足人数由电脑（AI）补位；

## 📝 联机机制说明

- **服务器权威**：房间状态只存在于服务器；客户端仅发送操作指令并接收按座位裁剪的安全快照；
- **协议**：见 `net-client.js` 头部注释（createRoom / joinRoom / resumeRoom / startGame / action / restart，及 roomInfo / state / error 广播）；
- **断线重连**：每个浏览器标签保存独立回座令牌；短暂断线自动重连并恢复原座位，超过宽限期由 AI 临时托管，之后凭有效令牌仍可重新取得控制；
- **AI 补位与托管**：使用创建房间时选择的难度（1~6）；
- **先手随机**：开局先手玩家随机，之后顺时针轮流。

## 📝 说明

- **牌库数值**：发展卡 90 张与贵族 10 位的数值取自 `splendor_base_data.js`（Splendor 基础版官方数据），`data.js` 已逐张核对一致（L1×40 / L2×30 / L3×20，每层每色 8/6/4 张；威望合计 5/55/80；含 L1 单色 4 成本 1 分卡、L2 单色 5/6 成本卡、L3 单色 7 成本 4 分卡等官方数值）；
- 防御性规则：极罕见情况下若当前玩家**没有任何合法行动**（预留已满、买不起、公共区宝石不足），按应急规则自动归还 1 枚筹码并结束回合，避免游戏卡死（联机由服务器自动处理，玩家会收到提示）；
- 卡面插画为占位主题图标（小动物 / 自然元素），修改 `data.js` 中的 `ART_POOL` 即可更换。
