# 05 · 测试体系

> 全部测试零外部依赖（ws 仅 test-net 用，已安装）。**任何改动后跑全量**：

```bash
npm test   # = test.js + ui-smoke.js + ui-strict-check.js + net-ui-check.js + test-net.js
```

## 1. test.js —— 核心逻辑（报告 524 断言）

- 覆盖：拿宝石规则、同色 2 枚阈值、购买/折扣/黄金支付、预留（明/盲/上限）、
  筹码上限归还、贵族（单/多）、AI 完整行动链、15 分终局完整轮次、重开清零、
  AI 规则专项、AI vs AI 整局、撤销上一回合、六档难度参数、3/4 人模式、
  固定卡位补牌 + lastAction 结构化。
- 技巧：`plantCard` 在测试中把指定卡放入 board（null 槽优先，否则替换槽 0 并推回牌堆）。
- 修改 `game.js` 后必跑；修改 `data.js` 后注意牌库守恒断言（每层 40/30/20，卡不重复）。

## 2. ui-smoke.js —— 界面冒烟（62 断言）

- 用 vm + 自制 DOM 桩加载全部浏览器脚本，模拟「主菜单 → 开始 → 回合交互 → AI 回合」。
- **桩会自动创建 index.html 中出现的所有 id**；`window.AI_SPEED=0.05` 加速 AI。
- 主要检查：菜单滑块、圆桌布局元素、座位渲染、宝石池、牌堆盲抽按钮、
  日志、归还弹窗等。

## 3. ui-strict-check.js —— 严格 DOM 桩（模拟真实浏览器）

- 与 ui-smoke 的区别：`getElementById` 找不到返回 **null**（真实浏览器行为），
  id 白名单从 `index.html` 静态解析。
- 目的：防止「stub 自动建 id 掩盖了真实浏览器会崩」的问题（曾因渲染顺序
  renderSelection 先于 renderPlayers 崩溃，被本测试抓出）。
- **给 ui.js 新增 `$('xxx')` 引用时，index.html 必须有对应 id，否则本测试会报错。**

## 4. net-ui-check.js —— 联机界面路径（22 断言）

- 加载完整脚本链（含 net-client.js），直接驱动 `SplendorNet` 回调：
  - 创建房间 → 等待区显示（表单隐藏、房间码、房主按钮、座位列表）；
  - 收到 state → 进入游戏（主菜单/大厅隐藏、房间码徽章、撤销/跳过隐藏）；
  - mySeat=1 → 主座位渲染「我」、对方带「👤 真人」标记；
  - 归还阶段 → 弹窗自动打开、returnOne 发送联机指令、乐观「已还×1」；
  - 掉线托管广播不崩溃；终局弹窗显示获胜者。
- **新增联机 UI 行为时，在此补断言。**

## 5. test-net.js —— 联机协议集成（约 32 断言，最慢 20~40 秒）

- 自动 `spawn('node server.js')`（随机端口，`stdio:'ignore'`——沙箱限制，勿改回 pipe）+ 多个 WS 客户端：
  - 静态服务：`/`、`/index.html`、`/game.js`、`/style.css`、query、规范化路径、
    目录穿越 403、404；
  - 房间：创建/加入/成员广播/权限（非房主开始被拒、不存在房间报错）；
  - 掉线座位开局自动 AI 托管；
  - 归还全流程：拿宝石攒到 >10 → 触发 discard → 归还/撤销归还（n=±1）→ finishDiscard；
  - 掉线托管：真人断开 → isAI=true → AI 自动完成回合；
  - 空房间清理。
- **测试基建（重要，别重写坏）**：
  - `wrap(ws)`：消息队列 + 按条件等待；**waiter 匹配用 findIndex 遍历全部等待者**
    （曾因只查 waiters[0] 导致并发等待超时）；
  - `waitTurn(c, seat)` / `humanTake(c, seat, label, opts)`：行动辅助，含回退链
    （拿 3 色 → 同色 2 枚 → 盲抽预留 → 买卡），`opts.manualDiscard=true` 时
    归还阶段不自动处理（供测试插入撤销归还断言）；
  - `autoPlay(c, seat)`：真人协程自动行动（推进另一真人回合，先手随机时必须）；
  - `settleAfterAction`：行动后自动处理多贵族 + 归还（**它会吞掉归还阶段**，
    需要观察归还流程的测试必须用 manualDiscard）。

## 6. 测试桩的公共限制（写测试时注意）

- 桩元素 `closest()` 恒返回 null → 事件测试传 `{target:{id:'...', closest:()=>null}}`。
- 桩没有 `querySelector`（只有 querySelectorAll）→ ui.js 已避免，新代码别用。
- `window.AudioContext` 不存在 → playSound 内部有 try/catch。
- vm 沙箱下 `WebSocket` 不存在 → net-client.js 的 connect() 不会被自动调用（无碍）。
