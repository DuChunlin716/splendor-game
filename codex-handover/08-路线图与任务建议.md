# 08 · 路线图与任务建议

> 候选任务按优先级排序。每个任务给出：范围 / 涉及文件 / 验收标准 / 风险。
> 接手后建议先完整走一遍「接手检查清单」，再从任务 A 开始。

## 接手检查清单（第一天）

1. `npm test` 全量通过（约 1 分钟）；
2. 双击 `index.html` 单机玩一局（选难度 1 与 6 各一局，确认手感差异）；
3. `node server.js` + 两个浏览器标签页联机一局（创建/加入/开始/操作/归还）；
4. 读一遍 02 与 03 的协议与数据结构；
5. 打开 `training/simulate_games.js` 跑一次确认训练基建可用。

## 任务 A：联机断线重连（推荐第一个做）

- **现状**：掉线即 AI 托管，刷新后需重进新房间，玩家体验中断。
- **范围**：协议加会话标识（如连接时携带 seatToken）；服务器保留断线座位一段时间
  （如 60 秒）不立即托管，同 token 重连恢复真人身份；前端断线后自动重连并恢复状态；
  超时仍托管。心跳（ping/pong）避免误判。
- **涉及**：server.js（会话/超时/重连）、net-client.js（token 存储、自动重连）、
  ui.js（重连提示 UI）、test-net.js（重连场景测试）。
- **验收**：掉线 <60s 刷新页面自动回到原座位继续玩；>60s 才托管；
  重连后状态与服务器一致；原有 32 项协议测试不回归。
- **风险**：中。注意重连窗口内 AI 不代走该座位（或代走但重连后同步）。

## 任务 B：房间列表 / 公开房间 / 房间码加强

- **现状**：房间码 4 位递增数字、无列表、无密码。
- **范围**：可选 —— 房间密码（joinRoom 带 pass）；公开房间列表页（roomInfo 广播
  房间列表给大厅）；房间码改为 6 位字母数字随机。
- **涉及**：server.js、net-client.js、ui.js（大厅加「公开房间」栏）、test-net.js。
- **验收**：能按密码加入；公开房在大厅可见可加入；原功能不回归。
- **风险**：低。注意列表广播频率（房间变化时推送即可）。

## 任务 C：删除「跳过本回合」测试按钮（已完成，2026-08-22）

- **完成内容**：已删除 ui.js renderBank 的 skipHtml、skipTurn 函数与导出、bind 里的 btn-skip 分支；
  ui-strict-check 与 net-ui-check 已同步改为验证正式操作区不存在该测试按钮。
- **验收**：按钮消失；测试全绿；无残留引用。
- **验证方式**：ui-strict-check 已改为使用真实的三色拿宝石行动推进回合，不再依赖测试入口。

## 任务 D：联机聊天

- **范围**：房间内文本聊天（action 类型 'chat' → 广播消息；UI 在 info-panel 加聊天框）。
- **涉及**：server.js、net-client.js、ui.js、style.css、test-net.js。
- **验收**：房内全员可见、带名字与时间；单机不受影响；协议测试覆盖。
- **风险**：低。注意消息长度限制与 XSS（渲染必须 esc）。

## 任务 E：观战模式

- **范围**：已开始房间允许只读加入（观战者收 state 但不能发 action）。
- **涉及**：server.js（seats 加 role）、net-client.js、ui.js（观战界面）、test-net.js。
- **验收**：观战者可见全部公开信息，发 action 被拒，不占玩家人数。
- **风险**：中。注意快照中隐藏信息（盲抽预留）对观战者同样隐藏。

## 任务 F：联机反滥用加固（公开运营前必做）

- **范围**：单 IP/连接数上限、action 频率限制（如 2 条/秒）、房间码枚举防护、
  消息体大小限制（ws maxPayload）。
- **涉及**：server.js（wss 选项 + 中间校验）、test-net.js。
- **验收**：压测脚本下服务器不崩、拒绝超频请求。
- **风险**：低。

## 任务 G：移动端打磨

- **范围**：触屏点击目标尺寸、横竖屏适配、字体缩放；音效在 iOS 的 AudioContext 解锁
  （首次触摸时 resume）。
- **涉及**：style.css、ui.js。
- **验收**：手机浏览器（含 iOS Safari）完整可玩一局。
- **风险**：低。

## 任务 H：CI 自动化（可选）

- **范围**：GitHub Actions 工作流：push 时跑 `npm test`（含 test-net），失败标红。
- **涉及**：新增 `.github/workflows/test.yml`（Node 20，`npm ci`，node test-net.js）。
- **验收**：push 后 Actions 全绿。
- **风险**：极低。注意 GitHub 沙箱无本机限制，`npm ci` 正常。

## 任务 I：性能与规模（暂不急）

- 状态广播全量快照：>6 人/大日志时优化为增量或分块（当前 2~4 人无压力）；
- 日志上限 400 条（game.js log 已有截断？确认后决定）。
