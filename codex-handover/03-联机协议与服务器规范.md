# 03 · 联机协议与服务器规范

> 协议完整定义在 `net-client.js` 头部注释；服务器实现在 `server.js`。改动协议时两处必须同步。

## 1. 消息协议

### 客户端 → 服务器
| 消息 | 说明 |
| --- | --- |
| `{type:'createRoom', playerCount, aiLevel, name}` | 创建房间（房主=座位 0） |
| `{type:'joinRoom', roomId, name}` | 加入房间（仅未开始时可加入） |
| `{type:'startGame'}` | 房主开始（掉线座位与不足人数由 AI 补位） |
| `{type:'action', action:{...}}` | 操作指令（见下） |
| `{type:'restart'}` | 房主重开（resetGame 保留玩家名单） |

### action 指令
| action | 说明 |
| --- | --- |
| `{type:'take', colors:[...]}` | 拿宝石（3 异色 或 同色 2 枚） |
| `{type:'buy', cardId}` | 购买公开/自己预留的卡 |
| `{type:'reserve', cardId}` | 明牌预留 |
| `{type:'blindReserve', tier}` | 盲抽预留（1|2|3 层） |
| `{type:'returnToken', color, n}` | 归还阶段：n=1 归还，n=-1 撤销归还 |
| `{type:'finishDiscard'}` | 归还完毕（≤10 枚） |
| `{type:'chooseNoble', nobleId}` | 多贵族择一 |

### 服务器 → 客户端
| 消息 | 说明 |
| --- | --- |
| `{type:'roomInfo', roomId, mySeat, playerCount, started, seats:[{name,connected}]}` | 房间信息（加入/成员变化时广播给相关连接） |
| `{type:'state', state, mySeat, roomId, started}` | 全量状态快照（每个连接带自己的 mySeat） |
| `{type:'error', message}` | 操作被拒原因（前端 flash 提示） |

## 2. 服务器权威要点（server.js）

1. **状态只存在服务器**：客户端只发指令，每次操作后 `sendState` 广播全量快照（JSON 深拷贝）。
2. **行动校验顺序**（handleAction）：
   - 游戏已开始 / 未结束 / 当前回合是该座位 / 该座位非 AI 托管；
   - 死局自动救济（phase=action 且无合法行动 → 归还 1 枚 + 结束回合）；
   - 阶段校验（action 类指令要求 phase='action'；returnToken/finishDiscard 要求 phase='discard'；
     chooseNoble 要求 pendingNobles 非空）；
   - 执行后：有 pendingNobles → 等待 chooseNoble；needDiscard → 设 phase='discard' 广播；
     否则 completeTurn → 广播 → 调度 AI。
3. **AI 调度**（scheduleAiTurn）：轮到 AI 座位（含补位与掉线托管）时
   `setTimeout(AI.executeAiTurn, 600~1000ms)` 模拟思考，执行后递归调度（连续 AI 回合）。
4. **掉线托管**：ws close → 该座位 `isAI=true`（名字保留）→ 广播 + 若轮到则调度 AI。
   开始游戏时 `!s.connected` 的座位也直接算 AI 补位。
5. **房间清理**：全部座位掉线后删除房间（房间码从 1000 递增，不回收）。
6. **无鉴权**：任何人知道房间码即可加入；房间码 4 位数字（可暴力枚举——已知限制，见 06）。

## 3. 快照与可观察性

- 广播快照 = `JSON.parse(JSON.stringify(state))`：**rng 函数会丢失**（前端不需要），
  `selection` 为空数组（前端本地维护），`aiGoal` 会保留（无害）。
- AI 决策使用 `buildObservableState`（ai.js）：对手预留只暴露数量，牌堆只暴露层数，
  **所有难度都看不到隐藏信息**（用户明确要求防作弊）。

## 4. 前端联机流程（net-client.js + ui.js）

1. `SplendorNet.connect()` → 创建/加入 → `onRoomInfo` 显示等待区（房间码/座位列表/开始按钮）。
2. 房主点开始 → 服务器广播首个 state → `onNetState` 进入游戏界面。
3. 回合内操作 → 发 action → 等广播 → `onNetState` 重新渲染。
4. 归还/贵族弹窗由广播状态自动开关；回合横幅按 currentPlayer 变化弹出。
5. 游戏结束 → 广播 gameOver → 结算弹窗（按排名展示，真人标记「真人」）。

## 5. 测试联机的方式

- 自动化：`node test-net.js`（自动起服务器 + 多 WS 客户端模拟，覆盖全部协议路径）。
- 手动：本地 `node server.js`，开两个浏览器标签页（或局域网两台设备）互连。
- 部署环境：Render/Railway 免费实例（见 07-部署运维.md）。
