# 01 · 项目现状与需求记录

## 1. 版本历史

| 版本 | 内容 |
| --- | --- |
| V1.0 | 第一版 2 人局（玩家 vs 电脑），纯逻辑 + 基础 UI，双击可玩 |
| V1.1~1.3 | 官方牌库数据接入、选宝石反馈、回合横幅、卡面 emoji 插画、撤销上一回合（3 次/局） |
| V1.4 | 六档电脑 AI 难度（1 新手 ~ 6 专家），L6 专家权重训练（2 人局） |
| V1.5 | 3/4 人模式（官方宝石/贵族数量）、多人局 AI 适配、L6 按人数分别训练权重 |
| V1.6 | 圆桌化 UI 重构 + 第二轮 UI 优化（固定卡位补牌、精确「上回合行动」、固定高度日志） |
| V1.7（当前） | 联机对战（服务器权威 + WebSocket + 房间制 + AI 补位/掉线托管）+ 公网部署配置 |

## 2. 当前功能清单（全部已完成并通过测试）

### 单机 / 通用
- 官方规则完整实现：拿宝石（3 异色 / 同色 2 枚需 ≥4）、预留（明牌/盲抽+黄金，上限 3）、
  购买（折扣 + 黄金万能支付）、10 枚筹码上限归还（可撤销归还）、贵族判定（多贵族择一）、
  15 分终局（完整轮次）、三档胜负（分数 → 卡少者胜 → 平局）
- 官方牌库：90 张发展卡（L1×40 / L2×30 / L3×20）+ 10 位贵族（每局人数+1 位）
- 2/3/4 人局：宝石 4/5/7 每色（黄金恒 5），贵族 3/4/5 位
- 六档 AI：L1 新手 / L2 简单 / L3 标准 / L4 困难 / L5 高手 / L6 专家
- 圆桌 UI：中央桌面（贵族+三层卡+宝石池）、围桌座位、右侧固定高度滚动日志、
  电脑「上回合行动」精确展示、固定卡位补牌动画、回合横幅、音效开关、规则弹窗、响应式
- 死局自动救济：无合法行动时自动归还 1 枚筹码并结束回合（单机弹窗提示，联机服务器自动）

### 联机（V1.7）
- 房间制：创建房间得房间码（从 1000 递增），2~4 人加入，不足由 AI 补位
- 服务器权威：所有操作由服务器执行并广播状态快照（客户端无法篡改）
- 掉线托管：真人断开后座位自动由 AI 接管（保留名字），游戏不中断
- 权限：仅房主可开始/重开；非当前回合者操作被拒；联机禁用「撤销/跳过回合」
- 联机 UI：大厅（昵称/人数/AI 难度/房间码/座位列表）、顶栏房间码徽章、真人/AI 标记、
  掉线托管横幅、通用结算排名
- 先手随机，逆时针/顺时针轮转（completeTurn 取模）

## 3. 用户需求记录（按时间线，含原文要点）

1. 「做一个能玩的璀璨宝石网页版，双击 index.html 就能玩」→ V1.0
2. 「用官方卡牌数值（splendor_base_data.js）」「预留卡不能超出桌面」「选宝石要有反馈」
   「回合开始结束要有提示」「卡面用 emoji 插画」→ V1.1~1.3
3. 「六档 AI 难度：1 新手~5 高手~6 专家；难度和人数直接在主菜单拉条选，不要点开再选」
   「L6 用自我对弈/进化训练权重」「AI 不能偷看牌堆和对手预留卡（可观察状态）」
   「控制台 AI_DEBUG 开关」→ V1.4（文档 `璀璨宝石小游戏——六档电脑AI难度系统开发提示词.md`）
4. 「3 和 4 人局的 AI 也要训练，难度和 2 人局对齐」→ V1.5（专家权重按人数分组）
5. 「圆桌化 UI：中间一张桌，玩家围坐，宝石池放桌上，日志放右侧」
   （文档 `璀璨宝石圆桌化UI重构提示词（含参考图）.md`）
6. 「第二轮 UI 优化：① 日志固定高度滚动、页面不能变长；② AI 座位显示精确的
   '上回合行动'（拿宝石显示颜色×数量；买卡显示卡牌/分值/原始成本；盲抽预留只显示层级+黄金，
   不能泄露卡面）；③ 买卡后新牌原位补入（固定 4 槽，不能整行移动）；④ 消除竖向空白」
   （文档 `璀璨宝石UI与交互第二轮优化提示词.md`）→ V1.6
7. 「下一步做联网模式，最终呈现为网址。2~4 真人 + 可选 AI 补位；直接公网部署；
   接受 Node.js + WebSocket」→ V1.7
8. 「跳过本回合」按钮是测试按钮，**最终版本要删除** → 已于 2026-08-22 从单机与联机操作区、事件处理及公开接口中完整移除。

## 4. 用户偏好补充

- 界面视觉基调：深色桌游风（深紫/金色），宝石用纯 CSS 圆形筹码 + emoji
- 难度显示：游戏中顶栏显示「难度 · Level N 名称」；结算界面按排名展示
- 用户遇到问题会直接贴现象（如「Render 部署后访问主页显示 Not Found」），
  期望先定位根因再修，修改范围最小化
